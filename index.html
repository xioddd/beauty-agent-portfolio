01 / 背景

业务问题与目标用户

业务问题

  • 资料分散且无核验：成分、功效、适用人群信息散落各处，资料不全时内容生产仍在"硬写"，埋合规隐患；
  • 初稿效率低、质量不稳：选题与文案依赖个人经验，新人上手慢；
  • 合规红线高发：美妆功效宣称受严格监管（如"抗老"非备案功效、医疗化表达禁用），靠人工事后审核成本高；
  • 种草与转化混为一谈：同一产品在不同业务目标、不同平台需要差异化表达，缺少标准化路径；
  • 生成结果无质控、无沉淀：一次性生成工具无法评估内容质量，也无法根据运营反馈持续改进。

目标用户与场景

  • 品牌内容运营：快速产出选题、标题、初稿，区分种草/转化目标；
  • 内容审核 / 合规岗：发布前识别功效表述风险并获得合规改写；
  • 新媒体新人 / 外包写手：按标准化结构与平台规范产出内容；
  • 核心场景：输入产品资料 + 目标用户 + 平台 + 内容目标，Agent 先核验资料、再走对应业务路径，输出可评估、可迭代的内容方案。
02 / 工作流

七步运营工作流

不是一次性文案生成器，而是带前置风控、业务分支、质控评分和反馈闭环的运营工作流。资料不全不硬写，风险表达直接给改写，每次输出可评分、可反馈、可迭代。

开始：产品资料 · 目标用户 · 平台 · 内容目标（种草/转化）

名称/卖点依据/人群/场景/可验证性 五项检查 · 不通过则退回补充，不生成正式文案
② 卖点提取 + 知识库检索

03 / 知识库

三类知识库分工（RAG 设计）

知识库不是"资料堆"，按检索意图拆成三类：产品事实、内容规范、平台规范分开维护，生成时各取所需，也便于后续按品牌/平台独立扩展。

RAG · 产品事实

产品资料库

  • 每款产品一张资料卡：官方卖点、成分、适用人群、场景、使用方法；
  • 已录入珀莱雅 5 款大单品：红宝石面霜/精华、双抗精华、源力精华、能量面霜；
  • 标注"官方不支持的表述"与资料来源、更新时间；
  • 价格/促销不入库，引导查官方旗舰店，避免过时信息。
RAG · 风控规则

内容规范库

  • 美妆用户 8 大常见关注点；
  • 内容风险红线：禁医疗化、禁虚构数据、禁绝对化；
  • 真实监管要点："抗老/抗初老"非药监局备案功效（备案为抗皱、紧致），美白需特证；
  • 检测数据引用规范（注明来源+保留条件）。
RAG · 平台策略

平台规范库

  • 小红书：搜索功课逻辑、图文结构、评论互动；
  • 抖音：前 3 秒钩子、口播节奏、短句、挂车转化；
  • 天猫/淘宝：详情信息、购买理由、疑虑前置解答；
  • 种草路径 vs 转化路径的内容差异。

EVALUATION-DRIVEN ITERATION · v2.2 → v2.3.1

量化评测闭环：从概率性合规到确定性合规

功能上线不等于质量可信。我为 Agent 建立了固定评测集与回归门禁，用 78 次可复现运行验证每一次修改的真实收益——这一环节直接驱动了 v2.3 的架构级修复。

80
固定评测用例

5 类场景：正例 28 · 跨版本干扰 16 · 合规对抗 25 · 缺信息拒答 7 · 多平台 4；每条带唯一判定标准（必含事实 / 禁止项 / 期望行为），杜绝主观打分。

40+40
冒烟集 + 全量门禁

40 条冒烟集支持快速回归，80 条全量集用于发布门禁；合规与跨版本类每条连测 3 次取最差结果，测量 LLM 非确定性，而非用一次好运代表真实水平。

2 层
分层归因

召回层看 recall slice 与相似度 Score（命中 / 排序列 / 阈值），生成层看最终回复；答错时可区分"没检索到"与"检索到但没用对"，修复才能精准落点。

第 1 轮基线：82.5%，以及被单次测试掩盖的红线漏放

v2.2 的 40 条冒烟基线首测通过率 87.5%，看似接近门禁。但对合规类引入"每条 3 次、最差计负"后，发现同一问题在不同运行中结果不一致：医疗化高风险问题三次复测中出现一次完全漏放，同一 Query 的召回 Score 在 1.00 与 0.58 间波动。按最差结果原则修订后，合规类真实通过率为 60%，总体基线修订为 82.5%。

根因：两道概率环节叠加，合规不能"靠运气"

召回侧

合规规则依赖语义 RAG 召回，规则片段常以 0.53–0.61 的低分进入甚至缺席，同一 Query 两次 Score 可从 1.00 波动到 0.58。

→
生成侧

平衡模式的生成随机性使模型是否执行拦截、是否给改写句不稳定，导致同一红线 case 时拦时放。

→
修复

高频红线与 8 类改写速查表内置于系统提示词最高优先级（全量在场，不依赖召回分数），强制"拦截 + 成句改写"双交付；模型切换精确模式；另补数值保真、版本确认前置、多产品搭配放行三条规则。

关键工程判断：没有调高知识库相似度阈值。基线数据显示 0.53–0.61 低分召回的恰恰是承担合规拦截的规则片段，提高阈值会直接误杀红线 case。正确方向是把合规从"概率性检索"升级为"确定性规则层"——安全能力不应建立在相似度运气之上。

修复过程：12 次高危验证中的 9/12 与再闭环

修复后先跑 4 条高危用例 × 3 次：结果 9/12——违规内容零漏放，但医疗化场景三次都漏掉"建议人工审核"标记。评测标准将其判为失败（行为完整度也是交付项），补一条硬性规则后重测 3/3 通过，再进入 78 次全量回归。这条"量化标准比模型自评更严格"的插曲，是评测机制真正在发挥约束作用的证据。

针对美妆内容运营中资料整理分散、初稿生产效率低、功效宣称合规风险高、种草与转化路径不分的问题，搭建美妆内容全链路智能运营 Agent：以资料核验门前置风控，以知识库（RAG）约束产品事实与合规用词，以种草/转化双路径对齐业务链路，并内置质量评分与反馈迭代机制。Agent 不替代运营判断，而是把运营经验沉淀为可复用、可评估、可持续优化的标准流程，后续可通过人工修改率、审核通过率、内容互动率与转化率衡量业务价值。

企业落地与后续优化

人工修改率
初稿到发布的人工改动比例，衡量内容生成质量
审核通过率
经风控检查后一次性通过合规审核的比例
互动与转化
内容收藏评论互动率、种草到下单链路转化率
方向一

工作流工程化

将七步流程固化为 Coze Workflow：风险句自动改写→复检→仍不通过转人工审核，形成"自动处理+人工兜底"的企业标准流程。

方向二

知识库产品化

产品库接入品牌官方 SKU 数据与备案信息，随新品同步；规范库扩展多品牌调性库，支持彩棠、Off&Relax 等多品牌内容风格。

方向三

运营台与数据闭环

搭建简易运营前端（资料输入→策略/文案/风控/评分分区展示）；接入平台热点与内容数据，反馈回流驱动选题与提示词迭代。
